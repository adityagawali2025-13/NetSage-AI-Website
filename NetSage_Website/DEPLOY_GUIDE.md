# NetSage AI: full deployment guide (GitHub + Render)

## Architecture
One Render Python web service hosts **both** the website and Flask backend. The browser calls same-origin `/api/...` URLs. No frontend URL changes or CORS configuration are needed.

- `index.html`, `styles.css`, `app.js`: frontend.
- `app.py`: Flask backend, API and static site host.
- `data/netsage_checker.py`: original deterministic rule engine.
- `data/cases.csv`, `data/ai_human_review.csv`: datasets.
- `data/project_data.js`: bundled data for the site to display even if API is offline.
- `requirements.txt`: installable backend dependencies.
- `render.yaml`: optional Render Blueprint deployment configuration.

## A. Run on Windows (VS Code)
1. Install Python 3.11+ and VS Code; unzip the project.
2. Open **NetSage_Website** folder (the folder with `app.py`) in VS Code.
3. Open Terminal → New Terminal.
4. Run:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

If activation is blocked by PowerShell policy, run without activation:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

5. Open http://127.0.0.1:8000 (not `index.html` as a file).
6. Verify the API at http://127.0.0.1:8000/api/health; expect `"status":"ok"`.
7. Click **Rule Diagnostics** → **Load sample** → **Run diagnostics**; the badge should say **PYTHON CHECKER**, with 6 findings for the provided sample.

## B. Upload code to GitHub
1. Sign in at https://github.com and click **+** → **New repository**.
2. Name it `netsage-ai-web`, choose private or public, then **Create repository**.
3. Open your new repository → **Add file** → **Upload files**.
4. Open the extracted `NetSage_Website` folder in Windows File Explorer. Select its **contents**, not the parent ZIP; drag them to GitHub's upload area. Include the `data` folder and all files within it. (If the web uploader does not retain nested folders, use Git as below.)
5. Commit the files. Ensure `app.py`, `requirements.txt`, `index.html` appear **at the repository root**, and `data/netsage_checker.py` is under `data/`.

**Reliable Git alternative in VS Code Terminal:**

```powershell
git init
git add .
git commit -m "NetSage AI full stack deploy"
git branch -M main
git remote add origin https://github.com/YOUR_USERNAME/netsage-ai-web.git
git push -u origin main
```

Replace `YOUR_USERNAME`. If your GitHub repo was initialized with a README, clone that repository first or reconcile the histories before pushing.

## C. Deploy on Render
1. Open https://dashboard.render.com and log in.
2. Choose **New** → **Web Service**.
3. Connect your GitHub account and select `netsage-ai-web`.
4. Enter the settings:

| Render setting | Value |
|---|---|
| Name | `netsage-ai` (or any available unique name) |
| Language/Runtime | `Python 3` |
| Branch | `main` |
| Root directory | leave empty (because app.py is at repo root) |
| Build command | `pip install -r requirements.txt` |
| Start command | `gunicorn --bind 0.0.0.0:$PORT app:app` |
| Instance type | `Free` for classroom testing if available |

5. Choose **Deploy Web Service**. Watch **Logs** until Render indicates the service is live.
6. Render gives your actual domain, e.g. `https://YOUR-SERVICE.onrender.com` (example only; your URL will differ).
7. Open `/api/health` on your domain; then open your main domain. Go to **Rule Diagnostics**, load sample and run it.
8. To update the site, edit your GitHub files and push a commit; Render automatically rebuilds if automatic deploy is enabled.

## D. Test API requests (PowerShell)
Local command:

```powershell
$body = Get-Content -Raw .\data\sample_cases.json
Invoke-RestMethod -Uri http://127.0.0.1:8000/api/check -Method POST -ContentType 'application/json' -Body $body
```

Replace URL with your deployed Render URL to test online. Other read-only endpoints: `/api/cases`, `/api/reviews`, `/api/stats`, `/api/health`.

## E. Important limitations
- The backend uses the uploaded deterministic Python checker; it does **not** contact a live AI model, Cisco devices, Packet Tracer or a database.
- The existing AI assessments and human reviews are records from your uploaded CSV, not newly generated by the server.
- A rule check identifies configured errors; no fix is automatically applied or verified.
- New human review submissions are not saved in this demonstration; persistent review editing would require authentication and a database.
- Render Free instances may sleep after inactivity and have an ephemeral filesystem; the dataset here is shipped with your code. Do not rely on local server files for permanent writes.
- Public access exposes the class-demo case data. Don't upload confidential network configs or secrets to an unauthenticated demo.

## F. Common fixes
- **ModuleNotFoundError: flask**: run `pip install -r requirements.txt` using the same Python environment running `app.py`.
- **gunicorn command not recognized on Windows**: use `python app.py` locally; `gunicorn` runs on Render's Linux environment.
- **Build fails, requirements not found**: ensure `requirements.txt` is in the Render root directory.
- **Page works, diagnostics say BACKEND OFFLINE**: check the Render logs and visit `/api/health` to verify the API.
- **404 on `/api/health`**: Render is serving the wrong project or a static site instead of the Python Web Service.
- **No cases shown**: check the `data` directory is committed, with CSV filenames unchanged.
